2. n8n을 Docker로 설치하고 방화벽 설정하기

n8n을 Docker 볼륨과 Docker Compose로 설치하는 방법과, Docker가 ufw를 우회하는 문제를 피해 5678 포트를 안전하게 여는 방화벽 설정을 정리했습니다.

Docker로 n8n을 설치하려면 데이터를 저장할 볼륨을 만들고 n8nio/n8n 이미지를 5678 포트와 함께 실행하면 됩니다. 방화벽은 ufw(Uncomplicated Firewall: 간편 방화벽) 같은 호스트 방화벽만 믿지 말고, 컨테이너 포트를 127.0.0.1에만 열고 앞단에 HTTPS 리버스 프록시(Reverse proxy: 요청을 대신 받아 내부 서버로 넘기는 서버)를 두는 방식으로 설정하는 것이 안전합니다. Docker가 공개한 포트는 ufw 규칙을 거치지 않기 때문입니다.

이 글은 n8n과 Docker 공식 문서를 기준으로 2026-11-03에 확인한 내용입니다. 작성 환경에서 Docker를 실행할 수 없어서 아래 명령은 직접 실행해 확인하지 못했고, 실행 결과 출력도 싣지 않았습니다. 공식 문서에 적힌 명령에서 포트 바인딩과 ufw 부분만 바꿨으므로 처음 실행할 때 동작을 꼭 확인하세요. 클라우드와 설치 버전의 차이, npm 설치는 1. n8n이란 무엇인가에 있습니다.

Docker 하나로 n8n 실행하기#

n8n 공식 문서의 Docker 설치 명령은 볼륨을 만들고 컨테이너를 실행하는 두 단계입니다. Docker Desktop은 macOS, Windows, Linux 모두에서 쓸 수 있고, 화면이 없는 Linux 서버에서는 Docker Engine과 Docker Compose를 따로 설치합니다. (Docker)

docker volume create n8n_data

docker run -it --rm \
  --name n8n \
  -p 5678:5678 \
  -e GENERIC_TIMEZONE="Asia/Seoul" \
  -e TZ="Asia/Seoul" \
  -e N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true \
  -v n8n_data:/home/node/.n8n \
  n8nio/n8n

-p 5678:5678은 호스트의 5678 포트를 컨테이너로 연결하며, 브라우저에서 http://localhost:5678로 접속합니다. TZ는 컨테이너 시스템 시간대이고, GENERIC_TIMEZONE은 Schedule Trigger 같은 시간 기반 노드가 쓰는 시간대입니다. 한국에서 쓴다면 둘 다 Asia/Seoul로 맞춰야 “매일 9시” 같은 예약 실행이 의도한 시각에 돕니다. -v n8n_data:/home/node/.n8n은 워크플로, 인증 정보, 실행 기록을 컨테이너 밖 볼륨에 두어서 컨테이너를 지워도 데이터가 남게 합니다. n8n은 기본으로 SQLite를 쓰며, PostgreSQL을 쓰는 경우에도 암호화 키가 들어 있는 .n8n 폴더는 볼륨으로 유지하라고 안내합니다. (Docker)

--rm과 -it는 터미널에서 시험해 볼 때의 설정입니다. 계속 돌리려면 --rm -it 대신 -d(백그라운드)와 --restart unless-stopped를 쓰거나 다음 절의 Docker Compose를 씁니다.

Docker Compose로 운영하기#

n8n 공식 문서는 Docker 설치 문서가 오래되었다고 밝히며 Docker Compose 설치를 권합니다. (Docker) Compose 파일은 컨테이너 설정을 파일로 남겨 두어 재현하기 쉽습니다. 공식 서버 설정 예시는 Traefik을 앞에 세워 80과 443 포트를 열고, n8n 컨테이너는 127.0.0.1:5678에만 연결하는 구성입니다. (Docker Compose) 이 구성에는 도메인이 필요하고, 사용하는 .env 파일은 아래 네 값을 채웁니다.

DOMAIN_NAME=example.com
SUBDOMAIN=n8n
GENERIC_TIMEZONE=Asia/Seoul
SSL_EMAIL=user@example.com

이렇게 하면 https://n8n.example.com으로 접속합니다. 서버의 공인 IP를 가리키는 A 레코드를 n8n.example.com에 먼저 만들어 두어야 하고, 시작은 sudo docker compose up -d, 업데이트는 docker compose pull, docker compose down, docker compose up -d 순서입니다. compose.yaml 전체는 공식 문서의 것을 그대로 받아 쓰는 것이 안전하므로 이 글에는 옮기지 않았습니다. 이 구성의 webhook 주소는 2.30.0부터 N8N_WEBHOOK_URL로 지정하며, 그 전 버전은 WEBHOOK_URL을 씁니다. (Docker Compose)

Docker가 방화벽 규칙을 우회하는 문제#

Docker로 공개한 포트는 ufw로 막아도 외부에서 접속될 수 있습니다. Docker 문서에 따르면 Docker는 공개 포트의 트래픽을 nat 테이블에서 처리하므로, ufw가 쓰는 INPUT, OUTPUT 체인보다 먼저 라우팅됩니다. 그 결과 ufw 설정이 이 포트에는 사실상 적용되지 않는다고 설명합니다. (Docker와 방화벽)

또 -p 5678:5678처럼 주소 없이 포트를 공개하면 모든 주소(0.0.0.0과 [::])에 공개됩니다. 반대로 -p 127.0.0.1:5678:5678처럼 루프백 주소를 앞에 쓰면 Docker 호스트에서만 그 포트에 접근할 수 있습니다. (포트 공개) 그래서 순서는 컨테이너 포트를 127.0.0.1로 묶어 막고, 바깥으로는 리버스 프록시가 쓰는 포트만 여는 것입니다.

컨테이너 포트를 127.0.0.1에만 열기#

단일 컨테이너라면 실행 명령의 -p만 바꿉니다.

docker run -d \
  --name n8n \
  --restart unless-stopped \
  -p 127.0.0.1:5678:5678 \
  -e GENERIC_TIMEZONE="Asia/Seoul" \
  -e TZ="Asia/Seoul" \
  -v n8n_data:/home/node/.n8n \
  n8nio/n8n

이렇게 하면 서버 안에서는 http://127.0.0.1:5678로 열리지만 같은 네트워크의 다른 PC는 접속할 수 없습니다. Docker 28.0.0 이전 버전에서는 같은 L2 구간의 호스트가 로컬호스트에 공개한 포트에 닿을 수 있었다고 Docker 문서에 적혀 있으니 Docker 버전도 확인하세요. (포트 공개)

ufw로 SSH, 80, 443만 허용하기#

호스트에는 리버스 프록시가 받을 80, 443 포트와 관리용 SSH만 엽니다. Ubuntu 문서의 ufw 명령은 아래와 같습니다. 원격 서버에서 ufw enable을 하기 전에 SSH를 먼저 허용하지 않으면 접속이 끊길 수 있으므로 순서를 지킵니다. (Ubuntu Server 방화벽)

sudo ufw allow ssh
sudo ufw allow 80
sudo ufw allow 443
sudo ufw enable
sudo ufw status verbose

관리용 SSH를 특정 주소에서만 받으려면 allow ssh 대신 sudo ufw allow proto tcp from 192.0.2.10 to any port 22처럼 출발지를 지정합니다. 이 방식은 호스트 프로세스로 들어오는 트래픽에 적용되고, Docker로 공개한 포트에는 적용되지 않는다는 점을 기억해야 합니다. 그래서 n8n 포트 5678은 ufw 규칙으로 막으려 하지 말고 앞에서 본 127.0.0.1 바인딩으로 막습니다.

5678 포트를 직접 열어야 할 때의 주의점#

도메인과 HTTPS 없이 http://서버IP:5678로 접속하면 로그인이 되지 않을 수 있습니다. n8n의 N8N_SECURE_COOKIE 설정은 기본값이 true이고, 쿠키를 HTTPS 연결로만 보내게 합니다. (n8n 보안 환경 변수) 이 값을 false로 바꾸면 HTTP에서도 쓸 수 있지만 쿠키가 암호화되지 않은 채 오가므로, 신뢰할 수 있는 내부망에서만 시험용으로 씁니다.

HTTPS 프록시 뒤에서 동작시키면 n8n이 만드는 webhook 주소가 틀릴 수 있습니다. 공식 문서는 n8n이 N8N_PROTOCOL, N8N_HOST, N8N_PORT로 주소를 조립하는데 프록시 뒤에서는 이 조합이 실제 주소와 달라진다고 설명하며 N8N_WEBHOOK_URL=https://n8n.example.com/과 N8N_PROXY_HOPS=1을 지정하라고 안내합니다. 프록시는 X-Forwarded-For, X-Forwarded-Host, X-Forwarded-Proto 헤더를 전달해야 합니다. (Webhook URL) 접속 확인은 설정을 바꾼 뒤 컨테이너를 다시 만들고, 바깥 PC에서 https://n8n.example.com이 열리는지, 같은 PC에서 서버IP:5678이 닫혀 있는지 두 가지를 모두 보는 방식이 확실합니다.

용어 설명#

ufw#

Uncomplicated Firewall. Ubuntu에서 방화벽 규칙을 쉬운 명령으로 관리하는 도구입니다. 처음에는 꺼져 있으므로 sudo ufw enable로 켭니다. (Ubuntu Server 방화벽)

리버스 프록시#

Reverse proxy. 외부 요청을 대신 받아 내부 서버로 전달하는 서버입니다. n8n 공식 Compose 예시에서는 Traefik이 이 역할로 HTTPS 인증서를 처리합니다. (Docker Compose)
