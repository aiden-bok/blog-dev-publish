1. Next.js 테스트 종류와 도구: Vitest, Jest, Playwright 비교

Next.js, React, Prisma, PostgreSQL로 만든 앱은 층마다 다른 도구로 테스트합니다. 함수와 컴포넌트는 Vitest나 Jest에 React Testing Library를 더해 확인하고, Prisma 쿼리는 실제 PostgreSQL을 띄워 확인하며, 화면 전체 흐름은 Playwright(E2E, End-to-End: 처음부터 끝까지 전체 흐름 테스트)로 확인하는 구성이 가장 무난합니다. async Server Component는 단위 테스트 도구가 아직 제대로 다루지 못해서 E2E로 확인하라는 것이 Next.js 공식 문서의 안내입니다.

이 글은 2026-11-04 기준으로 Next.js, Vitest, Jest, Playwright, Cypress, Prisma 공식 문서를 읽고 정리했습니다. 작성 환경에서는 예시 코드를 실행하지 못해 이 글에는 실행 결과를 싣지 않았고, 코드는 모두 공식 문서의 예시를 바탕으로 합니다. 도구를 설치하고 실제로 테스트를 작성하는 방법은 2. Next.js, Prisma, PostgreSQL 테스트 작성 방법에서 다룹니다.

테스트 종류와 확인하는 것#

테스트는 한 번에 확인하는 범위에 따라 단위, 컴포넌트, 통합, E2E로 나뉩니다. Next.js 문서도 이 분류를 쓰고, 여기에 렌더링 결과를 저장해 두었다가 비교하는 스냅샷 테스트를 더해 설명합니다. (Testing, Next.js Documentation)

종류확인하는 범위이 스택에서의 예
단위 테스트함수, 훅 하나를 따로가격 계산 함수, 입력값 검증 함수
컴포넌트 테스트React 컴포넌트의 렌더링과 이벤트 반응로그인 폼에 이메일을 넣으면 버튼이 켜지는지
통합 테스트여러 조각이 함께 동작하는지Route Handler가 Prisma를 거쳐 PostgreSQL에 저장하는지
E2E 테스트브라우저에서 사용자 시나리오 전체회원 가입부터 로그인까지
스냅샷 테스트렌더링 결과가 이전과 같은지컴포넌트 출력 비교

이슈에서 말한 기능별 테스트와 화면 테스트는 이 표에서 기준이 달라 보이는 것뿐입니다. 기능별 테스트는 보통 통합 테스트나 E2E로, 화면 테스트는 컴포넌트 테스트나 E2E로 작성합니다. 사용자 테스트는 실제 사람이 써 보고 불편한 곳을 찾는 방식이라 도구로 자동화하지 않습니다. 자동화한 테스트가 통과해도 사용하기 편한지는 알 수 없기 때문에, 출시 전에 사람이 직접 확인하는 단계는 따로 둡니다.

단위 테스트 도구: Vitest와 Jest#

Vitest와 Jest는 테스트를 실행하고 결과를 판정하는 테스트 러너입니다. Vitest는 Vite를 기반으로 하는 테스트 프레임워크이고 Vite 6.4.0 이상, Node.js 22.12.0 이상이 필요합니다. (Getting Started, Vitest) Jest는 오랫동안 쓰인 JavaScript 테스트 프레임워크로 npm install --save-dev jest로 설치합니다. (Getting Started, Jest)

두 도구 모두 Next.js 공식 가이드가 있습니다. Next.js 문서는 Jest를 단위 테스트와 스냅샷 테스트, Vitest를 단위 테스트용으로 소개합니다. 설정 방식이 다를 뿐 하는 일은 비슷하므로, 새로 시작한다면 Vitest를 쓰고 이미 Jest로 쌓아 둔 테스트가 있으면 그대로 두는 것이 부담이 적습니다. 이 판단은 공식 문서의 설명이 아니라 설정 비용을 기준으로 한 작성자의 정리입니다. 한 가지 주의할 점이 있습니다. Prisma 공식 테스트 가이드의 예시는 Jest 기준이어서, Vitest를 쓰면 같은 구조를 Vitest 문법으로 바꿔야 합니다.

컴포넌트를 테스트할 때는 러너에 React Testing Library를 더합니다. 이 라이브러리는 사용자가 소프트웨어를 쓰는 방식에 가깝게 테스트할수록 신뢰가 높아진다는 원칙으로 만들어졌습니다. (Guiding Principles, Testing Library) 그래서 컴포넌트 내부 상태가 아니라 화면에 보이는 제목, 버튼 이름 같은 결과로 확인합니다.

E2E 테스트 도구: Playwright와 Cypress#

Playwright와 Cypress는 실제 브라우저를 띄워 사용자처럼 화면을 조작하는 도구입니다. Playwright는 Chromium, WebKit, Firefox를 Windows, Linux, macOS에서 지원하고, Node.js는 최신 22.x, 24.x, 26.x가 필요합니다. (Installation, Playwright) Cypress는 E2E와 컴포넌트 테스트를 모두 지원하고, Firefox와 Chrome 계열 브라우저(Edge 포함)에서 실행합니다. (Why Cypress?, Cypress Documentation)

Next.js 문서에서 두 도구의 역할은 조금 다르게 소개됩니다. Playwright는 E2E 테스트용, Cypress는 E2E와 컴포넌트 테스트용입니다. Safari 엔진(WebKit)까지 확인해야 하면 Playwright, 컴포넌트를 실제 브라우저에서 확인하려면 Cypress가 선택지가 됩니다.

보조 도구: MSW와 Testcontainers#

외부 API 응답은 MSW(Mock Service Worker)로, 데이터베이스는 Testcontainers로 대신합니다. MSW는 브라우저와 Node.js에서 네트워크 요청을 가로채 원하는 응답을 돌려주는 라이브러리입니다. (Introduction, MSW) Testcontainers for Node.js는 테스트 코드 안에서 PostgreSQL 컨테이너를 만들고 접속 주소를 얻는 라이브러리입니다. 컨테이너를 직접 관리하는 대신 docker compose로 테스트용 DB를 띄우는 방법도 있고, Prisma 공식 가이드가 이 방법을 씁니다.

용어 설명#

CI#

Continuous Integration(지속적 통합). 코드를 저장소에 올릴 때마다 서버가 자동으로 빌드와 테스트를 실행하는 방식입니다. (GitHub Actions 문서, GitHub Docs)

E2E#

End-to-End(처음부터 끝까지). 실제 브라우저에서 사용자가 하는 행동을 그대로 따라 하며 앱 전체를 확인하는 테스트입니다. (Testing, Next.js Documentation)
