2. 기획자, 디자이너, 개발자, 운영자별 ChatGPT 활용법

기획자, 디자이너, 개발자, 운영자가 ChatGPT에 역할과 판단 기준을 알려 주고 결과를 검증하는 방법을 OpenAI 프롬프트 가이드 기준으로 직군별 프롬프트 예시와 함께 정리했습니다.
2026년 11월 5일 · 4 분 · 백업 담당자
목차
  • 모든 직군에 공통인 세 가지
  • 기획자는 결정할 것과 판단 기준을 준다
  • 디자이너는 문구와 검토 관점을 맡긴다
  • 개발자는 오류 문맥과 제약을 같이 준다
  • 운영자는 절차서와 점검 목록으로 쓴다
  • 결과를 검증하는 방법
  • 참고 자료

직군이 달라도 ChatGPT를 잘 쓰는 원리는 같습니다. 내 역할과 판단 기준을 알려 주고, 근거 자료를 직접 넣어 주고, 결과를 검증하는 것입니다. 달라지는 것은 어떤 자료를 넣고 무엇으로 검증하느냐입니다. 기본 프롬프트 틀은 1. 일반 사용자를 위한 ChatGPT 프롬프트와 설정에 있고, 주의할 점은 3. ChatGPT를 쓸 때 주의할 점에 있습니다.

OpenAI 가이드는 직군별 사용법을 따로 설명하지 않습니다. 이 글의 직군별 프롬프트는 가이드의 공통 원칙을 각 직군의 일에 맞춰 직접 적용한 예시이며, 실행해 확인한 결과가 아닙니다. 기준은 2026-11-05에 확인한 ChatGPT Enterprise Prompting Guide입니다.

모든 직군에 공통인 세 가지#

첫째, 역할을 정해 줍니다. 가이드는 Context 부분에 You are a program manager writing a weekly status update처럼 역할을 적는 예를 보여 줍니다. 둘째, 근거 자료를 직접 줍니다. 가이드는 필요한 원본 파일이나 연결된 앱이 없으면 프롬프트를 아무리 다듬어도 고칠 수 없다고 설명합니다. 셋째, 검증 장치를 요청에 넣습니다. 출처나 원문 인용을 요구하고, 불확실한 내용에는 (needs verification) 표시를 붙이게 하고, 가정한 내용을 따로 나열하게 합니다.

같은 직군이 반복해서 쓰는 자료와 지침은 프로젝트에 모아 둡니다. 프로젝트 지침은 전체 Custom Instructions보다 우선하므로, 직무마다 프로젝트를 하나씩 만들면 매번 역할을 다시 설명하지 않아도 됩니다. (Projects in ChatGPT)

기획자는 결정할 것과 판단 기준을 준다#

기획자는 요구사항을 정리하고 비교하는 일에 쓰기 좋습니다. 이때 결정해야 할 안건과 선택 기준을 반드시 같이 줍니다. 기준이 없으면 ChatGPT는 일반론으로 답합니다.

# 배경
나는 모바일 앱 기획자입니다. 아래는 지난 인터뷰 메모 10건입니다.
(메모 붙여넣기)

# 요청
반복해서 나오는 불편을 묶어서 3개 주제로 정리해 주세요.

# 조건
- 각 주제마다 메모에서 직접 인용한 문장을 1개씩 붙일 것
- 메모에 없는 내용은 쓰지 말고, 추측은 (needs verification)으로 표시
- 마지막에 가정한 내용을 따로 나열

디자이너는 문구와 검토 관점을 맡긴다#

디자이너는 화면의 마이크로카피 후보를 받거나 시안을 검토하는 관점을 얻는 데 쓸 수 있습니다. 이미지를 직접 올려 질문할 수도 있지만, 이 글에서는 이미지 입력을 확인하지 않았으므로 텍스트로 설명하는 방식만 예로 듭니다. 최종 판단은 사용자 테스트와 디자인 시스템 규칙으로 합니다.

# 배경
나는 결제 화면을 설계하는 디자이너입니다. 사용자는 50대 이상이 많습니다.

# 요청
결제 실패 안내 문구 후보 5개를 작성해 주세요.

# 조건
- 원인을 탓하는 표현 금지, 40자 이내
- 다음에 할 행동이 문구에 들어갈 것
- 후보마다 어떤 의도인지 한 줄로 설명

개발자는 오류 문맥과 제약을 같이 준다#

개발자는 오류 메시지만 던지지 않고 사용 중인 언어와 버전, 재현 조건, 이미 해 본 시도를 함께 줍니다. 그래야 같은 해결책을 다시 받지 않습니다. 코드 제안은 반드시 직접 실행해서 확인합니다. 가이드가 권하는 방식처럼, 정답을 아는 작은 문제 5~10개를 미리 만들어 ChatGPT의 답과 비교해 보는 것도 방법입니다.

# 배경
Node.js 24, Express 5 프로젝트입니다. 아래 오류가 POST /orders에서만 납니다.
(오류 로그 붙여넣기, 비밀 값은 제거)

# 요청
원인 후보를 가능성이 높은 순서로 3개 알려 주세요.

# 조건
- 후보마다 확인할 명령이나 코드 위치를 1개씩 제시
- 이미 시도한 방법: 서버 재시작, 의존성 재설치

개발 작업은 Codex 같은 별도 도구로도 할 수 있지만, 이 글에서는 해당 기능의 사용법을 확인하지 않았습니다.

운영자는 절차서와 점검 목록으로 쓴다#

운영자는 반복 업무의 점검 목록, 공지문, 장애 보고서 초안에 쓰기 좋습니다. 가이드가 든 예처럼 정기 업무 보고서 형태로 요청하면 형식이 일정해집니다.

# 배경
나는 쇼핑몰 운영자입니다. 어제 배송 지연 문의가 평소보다 많았습니다.
(문의 유형별 건수 표 붙여넣기)

# 요청
팀에 공유할 일일 운영 보고 초안을 작성해 주세요.

# 조건
- 표의 수치만 사용하고 계산이 필요하면 계산 과정을 함께 표시
- 원인은 확정하지 말고 가능성으로만 서술
- 마지막에 내일 확인할 항목 3개

결과를 검증하는 방법#

가이드는 ChatGPT에게 자기 답을 정확성, 완결성, 형식, 말투, 가정 표시 기준으로 다시 검토하게 하라고 제안합니다. 이 검토는 보조일 뿐이고, 숫자와 사실은 원본 자료와 직접 대조해야 합니다.
