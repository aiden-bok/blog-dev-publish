1. AWS SES 도메인 인증, DKIM, SPF, 샌드박스 해제

AWS SES에서 도메인 자격 증명을 만들고 DKIM CNAME과 MAIL FROM(SPF) 레코드를 등록해 인증한 뒤, 샌드박스를 해제해 아무에게나 보낼 수 있게 만드는 과정을 정리했습니다.

Amazon SES(Simple Email Service: 단순 이메일 서비스)로 메일을 보내려면 먼저 보내는 도메인을 SES에 등록하고 DNS(Domain Name System: 도메인 이름 시스템)에 레코드를 넣어 소유를 증명해야 합니다. 새 계정은 샌드박스 상태라 인증한 주소로만 보낼 수 있으므로, 실제 사용자에게 보내려면 샌드박스 해제도 요청해야 합니다. 이 글은 2026-11-05에 AWS 공식 문서를 확인해 순서대로 정리했고, 발송 방법은 2. AWS SES SMTP와 SDK로 메일 발송하기에서 다룹니다.

전체 순서는 도메인 자격 증명 생성, DKIM 레코드 등록, MAIL FROM 도메인 설정, 샌드박스 해제 요청의 네 단계입니다.

도메인 자격 증명 만들기#

SES 콘솔의 Identities에서 Create identity를 누르고 유형을 Domain으로 고른 뒤 도메인을 입력합니다. 도메인을 인증하면 하위 도메인과 그 도메인의 모든 주소에서 따로 인증하지 않고 보낼 수 있습니다. (Creating and verifying identities) 주소 하나만 인증하는 방법이 더 빠르지만, 운영 서비스라면 도메인 인증이 낫습니다.

도메인에는 www.를 붙이지 않고 example.com처럼 입력합니다. 붙이면 인증이 성공하지 않습니다. 자격 증명은 리전마다 따로 만들어야 하므로, 서울 리전(ap-northeast-2)에서 보낼 계획이라면 콘솔 리전을 서울로 바꾼 뒤 만듭니다. 같은 내용을 CLI로 하면 아래와 같습니다. 이 명령은 공식 문서에서 가져왔고 직접 실행해 확인하지는 못했습니다.

aws sesv2 create-email-identity --email-identity example.com --region ap-northeast-2

DKIM CNAME 레코드 등록#

DKIM(DomainKeys Identified Mail: 도메인 키 인증 메일)은 보낸 메일 헤더에 전자 서명을 넣고, 받는 서버가 DNS에 공개된 키로 그 서명을 확인하는 방식입니다. SES는 도메인 소유 확인에도 DKIM을 씁니다. 기본값인 Easy DKIM은 키 길이 2048비트로 SES가 서명을 맡으며, 사용자는 DNS에 CNAME 레코드 3개를 넣기만 하면 됩니다.

자격 증명 상세의 Authentication 탭에서 Publish DNS records를 펼치면 이름과 값이 나옵니다. 이름은 토큰._domainkey.example.com 꼴이고, 값은 토큰.dkim.리전.amazonses.com처럼 SES가 관리하는 주소입니다. 아래 표는 형식만 보여 주는 예시입니다.

이름유형값
abc123._domainkey.example.comCNAMEabc123.dkim.ap-northeast-2.amazonses.com

여기서 자주 틀리는 부분이 세 가지입니다. 이름 앞에 밑줄을 하나 더 붙이면 안 되고, _domainkey는 이름의 일부이니 콘솔에 나온 대로 입력해야 합니다. 일부 DNS 서비스는 입력한 이름 뒤에 example.com을 자동으로 붙이므로, 이름이 abc123._domainkey.example.com.example.com이 되지 않는지 확인합니다. Route 53에서 같은 계정의 도메인을 관리한다면 만들 때 레코드 게시를 켜 두면 SES가 직접 넣어 줍니다. (Creating and verifying identities)

레코드를 넣으면 SES가 확인하고 DKIM configuration이 Successful, Identity status가 Verified로 바뀝니다. DNS 변경이 퍼지는 데는 최대 72시간이 걸린다고 안내하지만, 확인 날짜 기준으로 실제 걸린 시간은 직접 측정하지 못했습니다.

SPF와 MAIL FROM 도메인#

SPF(Sender Policy Framework: 발신자 정책 프레임워크)는 어떤 서버가 해당 도메인 이름으로 메일을 보낼 수 있는지 DNS에 적어 두는 표준입니다. SES로 보내는 메일은 기본적으로 amazonses.com 하위 도메인을 MAIL FROM(봉투 발신자, 반송 주소)으로 쓰기 때문에 SPF 검사는 따로 설정하지 않아도 통과합니다. (Authenticating Email with SPF)

문제는 정렬(alignment)입니다. DMARC(Domain-based Message Authentication, Reporting and Conformance: 도메인 기반 메시지 인증, 보고, 적합성)는 받는 사람 눈에 보이는 From 도메인이 SPF나 DKIM 가운데 하나와 일치하길 요구합니다. 기본 MAIL FROM은 amazonses.com이라 SPF로는 정렬되지 않고, Easy DKIM 서명이 From 도메인과 맞아 DMARC는 DKIM으로 통과합니다. SPF까지 정렬하려면 직접 소유한 하위 도메인을 MAIL FROM으로 지정합니다.

자격 증명의 Custom MAIL FROM domain 패널에서 bounce.example.com 같은 하위 도메인을 입력하면 아래 두 레코드를 게시하라고 안내합니다. 이 하위 도메인은 다른 용도로 쓰지 않아야 하고, MX 레코드는 반드시 하나여야 합니다. (Using a custom MAIL FROM domain)

이름유형값
bounce.example.comMX10 feedback-smtp.ap-northeast-2.amazonses.com
bounce.example.comTXT"v=spf1 include:amazonses.com ~all"

MX의 숫자 10은 우선순위라서 DNS 서비스에 따라 별도 칸에 입력합니다. SES가 MX 레코드를 찾지 못하면 “Behavior on MX failure"에서 고른 대로 기본 MAIL FROM으로 대신 보내거나 발송을 거부합니다.

DMARC 레코드는 필수는 아니지만 _dmarc.example.com에 TXT로 넣을 수 있습니다. 공식 문서의 예는 "v=DMARC1;p=quarantine;rua=mailto:my_dmarc_report@example.com"이고, 처음에는 p=none으로 보고서만 받다가 quarantine, reject 순으로 올리라고 권합니다. (Complying with DMARC)

샌드박스에서 나오는 방법#

샌드박스는 새 SES 계정에 거는 제한으로, 리전마다 따로 적용됩니다. 샌드박스에서는 인증한 주소와 도메인 또는 SES 메일박스 시뮬레이터로만 보낼 수 있고, 24시간에 200통, 초당 1통으로 제한됩니다. 해제하면 수신자 주소를 인증하지 않아도 되지만, From 주소 등 보내는 쪽 자격 증명은 여전히 인증해야 합니다. (Request production access)

콘솔의 Account dashboard에서 View Get set up page, Request production access를 차례로 눌러 요청합니다. 입력 항목은 아래와 같습니다.

  • 메일 유형: Transactional(회원가입 확인처럼 사용자 행동에 따른 1대1 메일)과 Marketing(다수에게 보내는 홍보 메일) 가운데 대부분을 차지하는 쪽
  • 웹사이트 주소와 추가 연락 이메일(최대 4개), 선호 언어(영어 또는 일본어)
  • 수신 동의를 받은 사람에게만 보내고 반송과 수신 거부를 처리하는 절차가 있다는 확인

CLI로는 aws sesv2 put-account-details --production-access-enabled --mail-type TRANSACTIONAL --website-url https://example.com --additional-contact-email-addresses info@example.com --contact-language EN을 씁니다. AWS Support의 첫 응답은 96시간 안에 온다고 안내합니다. 도메인을 먼저 인증해 두면 승인이 빨라지는 모범 사례라고 문서가 밝히므로, 이 글의 순서대로 인증을 끝낸 뒤 요청하는 편이 좋습니다. 직접 요청해 본 결과는 이 글에 싣지 못했습니다.

용어 설명#

SES#

Amazon Simple Email Service. AWS가 제공하는 이메일 발송 서비스로, SMTP 또는 API로 메일을 보냅니다. (What is Amazon SES?)

DNS#

Domain Name System. 도메인 이름을 IP 주소와 인증 정보 같은 레코드로 바꿔 주는 이름 체계입니다. (RFC 1034)

DKIM#

DomainKeys Identified Mail. 메일에 전자 서명을 넣고 DNS의 공개 키로 검증하는 방식입니다. (RFC 6376)

CNAME#

Canonical Name 레코드. 한 도메인 이름을 다른 이름의 별칭으로 연결하는 DNS 레코드입니다. (RFC 1034)

SPF#

Sender Policy Framework. 도메인 대신 메일을 보낼 수 있는 서버를 DNS TXT 레코드로 선언하는 표준입니다. (RFC 7208)

DMARC#

Domain-based Message Authentication, Reporting and Conformance. SPF나 DKIM 결과가 From 도메인과 맞는지 보고, 실패한 메일의 처리 정책을 알리는 표준입니다. (RFC 7489)
