n8n은 트리거와 작업 노드를 선으로 이어 반복 업무를 자동화하는 워크플로 도구입니다. 같은 n8n을 n8n이 대신 운영해 주는 클라우드 버전으로 쓰거나, 내 서버와 PC에 직접 설치해서 쓸 수 있습니다. 구독료와 실행 횟수 제한을 감수하고 관리를 맡기려면 클라우드, 데이터를 내 환경에 두고 관리를 직접 하려면 설치 버전을 고르면 됩니다.

이 글은 n8n 공식 문서를 기준으로 2026-11-03에 확인한 내용을 정리했습니다. 이 글의 작성 환경에서는 설치와 실행을 직접 해 보지 못해, 명령어는 공식 문서에 적힌 그대로 옮겼고 실행 결과 출력은 싣지 않았습니다. Docker로 설치하고 방화벽을 설정하는 방법은 2. n8n을 Docker로 설치하고 방화벽 설정하기에 나눠 두었습니다.

n8n은 무엇을 하는 도구인가#

n8n의 워크플로는 시작점인 트리거(Trigger)와 그 뒤에 이어지는 노드(Node)로 이루어집니다. 공식 튜토리얼에서는 정해진 시간에 실행되는 Schedule Trigger로 워크플로를 시작하고, 각 노드가 작업 하나를 처리해 결과를 다음 노드로 넘기는 구조로 설명합니다. (Try it out) 외부 서비스가 보낸 요청을 받는 웹훅 트리거도 있어서, 메신저나 메일, 데이터베이스를 연결하는 일에 많이 씁니다.

클라우드 버전과 설치 버전의 차이#

n8n을 쓰는 방법은 크게 n8n Cloud와 셀프 호스팅(Self-hosted) 두 가지이고, 셀프 호스팅은 다시 무료 Community 버전과 유료 Business, Enterprise 버전으로 나뉩니다. (Choose your n8n) 설치 버전에서 라이선스 키 없이 쓰는 것이 Community 버전입니다.

비용: 실행 횟수로 나뉘는 요금제#

클라우드 요금제는 한 달에 실행할 수 있는 워크플로 횟수로 갈립니다. 2026-11-03에 확인한 가격 페이지에서 연간 결제 기준 Starter는 월 20유로에 2,500회, Pro는 월 50유로에 10,000회였고, Enterprise는 문의해서 정합니다. 셀프 호스팅 Business는 월 667유로(연간 결제)에 40,000회로 표시되어 있었습니다. (n8n Pricing) 가격과 한도는 자주 바뀌므로 결제 전에 가격 페이지를 다시 확인하세요.

Community 버전은 무료이고, 이메일을 등록하면 폴더, 편집기 안 디버그, 사용자 지정 실행 데이터 같은 기능을 추가 비용 없이 쓸 수 있습니다. 반면 SSO(Single Sign-On: 통합 인증), 프로젝트, 환경, 외부 시크릿, Git 버전 관리는 설치 버전이라도 유료 버전에서만 열립니다. (Choose your n8n)

관리 범위: 업데이트와 백업은 누가 하는가#

클라우드는 호스팅과 업데이트, 확장을 n8n이 맡습니다. 설치 버전은 서버 준비부터 업데이트, 데이터 백업, 보안 설정, 외부 접속 설정까지 직접 해야 합니다. 설치 버전이 무료여도 서버 비용과 관리 시간이 든다는 점이 실제로 가장 크게 갈리는 부분입니다. Docker Compose 설치 문서도 직접 호스팅은 숙련된 사용자 대상이며 그렇지 않으면 n8n Cloud를 권한다고 안내합니다. (Docker Compose)

라이선스: 무료 버전으로 무엇까지 할 수 있는가#

n8n 소스는 Sustainable Use License로 공개되어 있습니다. 라이선스는 소프트웨어를 자기 회사의 내부 업무 목적이나 비영리, 개인 목적으로만 쓰거나 수정하도록 허용하고, 무료이면서 비영리인 경우가 아니면 다른 사람에게 배포하는 것을 금지합니다. (n8n LICENSE.md) 우리 팀의 업무 자동화에 쓰는 것은 문제가 없지만, n8n을 포함한 서비스를 고객에게 판매하려는 경우에는 라이선스를 직접 읽거나 n8n에 문의해야 합니다.

어떤 쪽을 고를까#

개인이 가볍게 시험해 보거나 서버를 관리할 여력이 없으면 클라우드의 14일 체험으로 시작하는 편이 빠릅니다. 사내 데이터를 외부에 두기 어렵거나 월 실행 횟수에 따른 요금이 부담된다면 설치 버전을 고릅니다. 대신 서버 비용과 관리 시간을 직접 감당해야 합니다.

설치 방법의 종류와 Node.js 요구 사항#

설치 버전은 Docker, Docker Compose, npm(Node Package Manager: Node.js 패키지 관리자) 가운데 하나로 설치합니다. 공식 호스팅 문서는 데이터베이스까지 갖춘 운영 환경에는 Docker Compose를 안내하고, npm 설치는 n8n 3.0부터 지원이 중단될 예정(deprecated)이라고 밝힙니다. (Hosting n8n, npm) 그래서 오래 쓸 환경은 Docker가 낫고, 이 글에서는 운영체제별 차이가 드러나는 npm 설치를 먼저 설명합니다.

npm 설치에는 Node.js 20.19 이상 24.x 이하가 필요합니다. (npm) 설치 전에 터미널에서 버전부터 확인합니다.

node -v
npm -v

운영체제별 npm 설치#

세 운영체제 모두 Node.js를 설치한 뒤 같은 npm 명령으로 n8n을 설치하고 실행합니다. 차이는 Node.js 설치 방법과 터미널 종류뿐입니다. Node.js 설치 파일은 Node.js 다운로드 페이지에서 운영체제에 맞게 받습니다.

Windows#

Node.js 설치 파일을 받아 실행하고, PowerShell을 새로 열어 node -v로 버전이 나오는지 확인합니다. npm 문서는 Windows에서 문제가 생기면 Node.js 설치 상태를 먼저 점검하라고 안내합니다. 설치와 실행 명령은 PowerShell에서 아래와 같이 씁니다.

macOS#

macOS도 Node.js 설치 파일을 쓰거나, 패키지 관리자를 이미 쓰고 있다면 그쪽으로 Node.js를 설치합니다. 터미널을 새로 열어 node -v를 확인한 뒤 같은 명령을 씁니다.

Linux#

배포판 저장소의 Node.js 버전이 20.19보다 낮을 수 있으므로 node -v로 반드시 확인합니다. 낮다면 Node.js 사이트에서 안내하는 방법으로 더 높은 버전을 설치합니다. 전역 설치(-g)가 권한 오류로 막히면 sudo를 붙이기 전에 npm의 전역 설치 경로 설정부터 확인하는 것이 안전합니다.

설치와 실행 명령#

설치하지 않고 한 번만 실행해 보려면 npx n8n을 씁니다. 전역으로 설치해 두고 쓰려면 아래 명령을 실행합니다.

npm install n8n -g
n8n

실행하면 브라우저에서 http://localhost:5678로 접속합니다. 업데이트는 npm update -g n8n, 특정 버전 설치는 npm install -g n8n@버전입니다. 업그레이드 중 데이터베이스 마이그레이션이 있었다면 이전 버전을 다시 설치한 뒤 n8n db:revert로 되돌립니다. npm으로 설치한 n8n에서는 n8n Assistant를 쓸 수 없습니다. (npm)

webhook으로 외부 서비스의 요청을 받으려면 인터넷에서 접근 가능한 주소가 필요합니다. 집이나 사무실 PC에서 localhost:5678로만 띄운 n8n은 외부 서비스가 접근할 수 없으므로, 서버에 설치하고 도메인과 HTTPS를 연결하는 방법을 2편에서 다룹니다.

용어 설명#

워크플로#

Workflow. n8n에서 트리거와 노드를 순서대로 이어 만든 자동화 작업 하나를 뜻합니다. (Try it out)

SSO#

Single Sign-On(통합 인증). 한 번 로그인하면 여러 서비스를 다시 로그인하지 않고 쓰는 방식입니다. n8n에서는 유료 버전에서 쓸 수 있는 기능입니다. (Choose your n8n)

npm#

Node Package Manager. Node.js 패키지를 설치하고 관리하는 도구입니다. n8n은 npm install n8n -g로 설치할 수 있습니다. (npm 설치 문서)

웹훅#

Webhook. 외부 서비스가 특정 사건이 생길 때 지정한 주소로 HTTP 요청을 보내 알려 주는 방식입니다. n8n의 Webhook 노드가 이 요청을 받습니다. (n8n Webhook node)
