2. GitHub Actions, Pages, Releases, Codespaces로 자동화하기

GitHub Actions로 검사를 자동화하고, Pages로 사이트를 게시하고, Releases로 배포본을 묶고, Codespaces로 브라우저에서 개발하는 방법과 무료 사용량을 정리했습니다.

GitHub Actions는 저장소에서 일어난 일을 계기로 검사와 배포를 자동으로 실행하는 기능이고, 같은 계정에서 Pages로 정적 사이트를 게시하고 Releases로 배포본을 묶고 Codespaces로 클라우드 개발 환경을 열 수 있습니다. 이 글은 소스 저장소로만 쓰던 사용자가 저장소 밖의 작업까지 GitHub 안에서 처리하는 방법을 정리했습니다.

협업 기능은 1. GitHub 이슈, 풀 리퀘스트, 프로젝트로 협업하기, 보안 설정은 3. GitHub 계정과 저장소 보안 설정하기에 있습니다. 기준은 2026-11-06에 확인한 GitHub Docs입니다. 무료 사용량은 요금제와 시점에 따라 바뀌므로 적용 전 계정의 청구 화면도 확인합니다. 워크플로 파일은 예시를 싣지 않았고, 이 글에 직접 실행한 결과는 없습니다.

GitHub Actions로 검사와 배포 자동화하기#

GitHub Actions의 워크플로(workflow)는 하나 이상의 작업(job)을 실행하는 자동화 절차로, 저장소의 YAML 파일에 정의합니다. 이벤트가 일어나거나 사용자가 직접 요청하거나 일정에 따라 실행됩니다. (Understanding GitHub Actions)

용어는 네 가지만 알면 됩니다. 이벤트(event)는 풀 리퀘스트를 열거나 커밋을 푸시하는 것처럼 워크플로를 시작시키는 저장소 안의 활동입니다. 작업(job)은 같은 러너에서 실행되는 단계들의 묶음이며 기본적으로 병렬로 실행됩니다. 러너(runner)는 워크플로를 실제로 실행하는 서버이고 한 번에 작업 하나를 맡습니다. 워크플로 파일은 저장소의 .github/workflows 디렉터리에 두며, 파일을 여러 개 둘 수 있습니다.

흔한 용도는 풀 리퀘스트가 열릴 때 테스트와 문법 검사를 돌리는 것입니다. 1편의 풀 리퀘스트와 결합하면 검사를 통과한 변경만 병합하는 흐름이 만들어집니다.

무료 사용량#

공개 저장소에서는 표준 GitHub 호스티드 러너가 무료이고 포함 사용량에서 차감되지 않습니다. 비공개 저장소는 분 단위가 아니라 금액으로 표시된 포함 사용량이 월마다 주어집니다. (GitHub Actions billing)

요금제월 포함 사용량아티팩트 저장소캐시 저장소(저장소당)
GitHub Free12달러500MB10GB
GitHub Pro18달러1GB10GB
GitHub Team18달러2GB10GB

아티팩트 저장소는 GitHub Packages와 나누어 씁니다. 캐시 저장소는 별도 한도입니다.

GitHub Pages로 사이트 게시하기#

GitHub Pages는 저장소의 HTML, CSS, JavaScript 파일을 게시하는 정적 사이트 호스팅 서비스이고, 빌드 단계는 선택입니다. 사용자 또는 조직 사이트는 <owner>.github.io 이름의 저장소에 두며 계정당 하나, 프로젝트 사이트는 저장소마다 하나입니다. github.io 주소나 직접 가진 도메인을 쓸 수 있습니다. (What is GitHub Pages?)

게시 방식은 두 가지입니다. 브랜치에서 배포하는 방식은 고른 브랜치에 푸시하면 게시되며 저장소 루트나 /docs 폴더를 지정합니다. GitHub Actions 방식은 직접 만든 워크플로로 빌드해서 Jekyll 외의 도구도 쓸 수 있고, 빌드 결과물을 위한 전용 브랜치가 필요 없습니다. 이 블로그처럼 Hugo로 만든 사이트는 후자에 해당합니다. 어느 쪽이든 저장소가 비공개여도 사이트는 누구나 볼 수 있다는 점은 주의해야 합니다. (Configuring a publishing source)

Releases로 배포본 묶기#

릴리스는 소프트웨어를 다른 사람이 내려받아 쓸 수 있게 묶은 배포 단위이며, Git 태그를 바탕으로 합니다. 릴리스에는 릴리스 노트, 첨부 파일, 소스 아카이브가 들어갑니다. 릴리스 노트는 직접 쓰거나 템플릿으로 생성할 수 있고, 첨부 파일은 릴리스당 최대 1,000개, 파일당 2GiB 미만입니다. 태그가 가리키는 시점의 소스는 zip과 tarball로 자동 제공됩니다. (About releases)

태그를 만든 날과 릴리스를 만든 날은 다를 수 있습니다.

Codespaces로 브라우저에서 개발하기#

Codespace는 클라우드에서 실행되는 개발 환경입니다. 각 codespace는 가상 머신 위의 Docker 컨테이너에서 돌아가며, 2코어 8GB RAM 32GB 저장소부터 32코어 128GB RAM 128GB 저장소까지 사양을 고를 수 있습니다. 템플릿이나 저장소의 어느 브랜치, 커밋에서도 만들 수 있고, 브라우저, Visual Studio Code, GitHub CLI로 접속합니다. (What are GitHub Codespaces?)

Free와 Pro 개인 계정에는 월 무료 사용량이 있고, Free는 월 120시간의 컴퓨트와 15GB-월 저장소, Pro는 180시간과 20GB-월입니다. 다만 이 시간은 머신의 코어 수만큼 배수가 곱해져 차감되는 것으로 보이므로, 정확한 계산은 계정의 사용량 보고서에서 확인합니다. 결제 수단이 없으면 한도에 닿을 때 사용이 멈춥니다. (GitHub Codespaces billing)
