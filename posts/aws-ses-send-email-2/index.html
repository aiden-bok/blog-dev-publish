2. AWS SES SMTP와 SDK로 메일 발송하기

AWS SES로 메일을 보내는 두 방법인 SMTP 인터페이스와 API를 비교하고, SMTP 자격 증명 발급, Nodemailer 연동, AWS SDK for JavaScript v3의 SendEmailCommand 코드를 정리했습니다.

SES로 메일을 보내는 방법은 SMTP(Simple Mail Transfer Protocol: 간이 메일 전송 규약) 인터페이스와 API 두 가지입니다. 기존 코드나 메일 라이브러리를 그대로 쓰고 싶으면 SMTP, 새로 만드는 서버 코드라면 AWS SDK(Software Development Kit: 소프트웨어 개발 키트)로 API를 호출하는 쪽이 설정이 단순합니다. 도메인 인증과 샌드박스 해제가 끝났다는 전제로 쓴 글이며, 앞 단계는 1. AWS SES 도메인 인증, DKIM, SPF, 샌드박스 해제에 있습니다.

이 글의 코드는 Node.js 24에서 쓰도록 작성했습니다. 작성 환경에는 AWS 계정과 자격 증명이 없어서 실제로 발송해 보지 못했으므로, 실행 결과는 싣지 않았습니다. 도메인과 주소는 모두 example.com 같은 예시 값입니다.

SMTP와 API 중 무엇을 고를까#

두 방법은 인증 정보가 서로 다릅니다. SMTP는 SES 전용 SMTP 사용자 이름과 비밀번호를 쓰고, 이 비밀번호는 AWS 비밀 액세스 키와 같지 않습니다. (Obtaining Amazon SES SMTP credentials) API는 SDK가 AWS 자격 증명으로 요청을 서명해 주고, 재시도와 오류 처리도 SDK가 맡습니다. (Using the Amazon SES API to send email)

SMTP로 보내기#

SMTP로 보내려면 엔드포인트 주소, 포트, SMTP 자격 증명이 필요합니다. 서울 리전의 엔드포인트는 email-smtp.ap-northeast-2.amazonaws.com입니다. (Amazon SES endpoints and quotas) 연결은 반드시 TLS(Transport Layer Security: 전송 계층 보안)로 암호화해야 합니다. 25, 587, 2587 포트는 STARTTLS로 연결을 올리고, 465와 2465 포트는 처음부터 TLS로 연결합니다. (Connecting to an Amazon SES SMTP endpoint) EC2에서는 기본으로 25번 포트 트래픽을 제한하므로 587을 쓰는 편이 안전합니다.

SMTP 자격 증명은 SES 콘솔의 SMTP settings에서 Create SMTP credentials를 눌러 만듭니다. 그러면 IAM 콘솔이 열리고 SMTP 전용 사용자가 만들어지며, 비밀번호는 이 화면을 닫으면 다시 볼 수 없으니 바로 저장해야 합니다. 자격 증명은 리전마다 따로이고, 이 사용자에게는 ses:SendRawEmail 권한이 필요합니다. (Obtaining Amazon SES SMTP credentials)

Node.js에서는 Nodemailer로 연결하는 방식이 흔합니다. 아래 코드는 587 포트에서 STARTTLS를 쓰는 설정입니다.

import nodemailer from "nodemailer";

const transporter = nodemailer.createTransport({
  host: "email-smtp.ap-northeast-2.amazonaws.com",
  port: 587,
  secure: false, // 587은 연결 후 STARTTLS로 올립니다. 465를 쓸 때만 true
  auth: {
    user: process.env.SES_SMTP_USER,
    pass: process.env.SES_SMTP_PASSWORD,
  },
});

const info = await transporter.sendMail({
  from: '"Example" <no-reply@example.com>',
  to: "recipient@example.com",
  subject: "SES SMTP 테스트",
  text: "SMTP로 보낸 본문입니다.",
  html: "<p>SMTP로 보낸 본문입니다.</p>",
});

console.log(info.messageId);

사용자 이름과 비밀번호는 코드에 적지 않고 환경 변수나 AWS Secrets Manager에서 읽습니다. 공식 SMTP 예제도 정적 자격 증명을 권하지 않는다고 경고합니다. (Sending emails programmatically through the Amazon SES SMTP interface) from 주소는 인증한 도메인에 속해야 하고, 샌드박스 상태라면 받는 주소도 인증한 주소여야 합니다.

AWS SDK for JavaScript v3로 보내기#

SES API v2는 @aws-sdk/client-sesv2 패키지의 SendEmailCommand로 호출합니다. 확인 시점의 최신 버전은 3.1162.0이고 Node.js 20 이상이 필요합니다. (npm registry) 설치는 npm install @aws-sdk/client-sesv2입니다.

import { SESv2Client, SendEmailCommand } from "@aws-sdk/client-sesv2";

// 자격 증명은 SDK 기본 체인(환경 변수, 공유 설정 파일, IAM 역할)에서 읽습니다.
const client = new SESv2Client({ region: "ap-northeast-2" });

const command = new SendEmailCommand({
  FromEmailAddress: "no-reply@example.com",
  Destination: { ToAddresses: ["recipient@example.com"] },
  Content: {
    Simple: {
      Subject: { Data: "SES SDK 테스트", Charset: "UTF-8" },
      Body: {
        Text: { Data: "SDK로 보낸 본문입니다.", Charset: "UTF-8" },
        Html: { Data: "<p>SDK로 보낸 본문입니다.</p>", Charset: "UTF-8" },
      },
    },
  },
});

const response = await client.send(command);
console.log(response.MessageId);

Simple은 SES가 MIME 메시지를 대신 조립해 주는 방식입니다. 첨부 파일이나 헤더를 직접 다루려면 Raw를, 템플릿에 값을 채워 보내려면 Template을 씁니다. (Using the Amazon SES API to send email) 코드 구조는 SDK 문서 기준으로 작성했고, 실제 호출은 확인하지 못했습니다.

실행하는 IAM 사용자나 역할에는 ses:SendEmail 권한이 필요하며, Resource를 인증한 자격 증명의 ARN으로 좁힐 수 있습니다. (Identity and access management in Amazon SES) EC2나 Lambda에서는 액세스 키를 만들지 않고 IAM 역할을 붙이는 방식이 키 유출 위험이 적습니다.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "ses:SendEmail",
      "Resource": "arn:aws:ses:ap-northeast-2:123456789012:identity/example.com"
    }
  ]
}

발송이 실패할 때 확인할 것#

샌드박스에서 인증하지 않은 주소로 보내면 거부되므로, 먼저 받는 주소를 인증했는지 봅니다. 리전이 다르면 자격 증명이 없는 것으로 처리되므로 코드의 region과 콘솔 리전이 같은지도 확인합니다. SMTP에서는 인증 실패가 흔한데, AWS 액세스 키를 SMTP 비밀번호로 잘못 넣은 경우가 대부분입니다. 메일이 들어갔는데 스팸함에 있다면 1편의 DKIM과 MAIL FROM 상태가 Successful인지 먼저 봅니다. 시험 발송에는 SES 메일박스 시뮬레이터 주소를 쓰면 발송 한도와 반송률에 반영되지 않습니다. (Sending emails programmatically through the Amazon SES SMTP interface)

용어 설명#

SMTP#

Simple Mail Transfer Protocol. 메일 서버끼리, 그리고 클라이언트가 서버로 메일을 보낼 때 쓰는 표준 프로토콜입니다. (RFC 5321)

SDK#

Software Development Kit. 특정 서비스의 API를 프로그래밍 언어에서 편하게 호출하도록 만든 라이브러리 묶음입니다. (AWS SDKs and Tools)

TLS#

Transport Layer Security. 네트워크 연결을 암호화하고 상대를 확인하는 프로토콜입니다. (RFC 8446)

STARTTLS#

일반 SMTP 연결을 시작한 뒤 TLS 암호화 연결로 올리는 SMTP 확장입니다. (RFC 3207)
