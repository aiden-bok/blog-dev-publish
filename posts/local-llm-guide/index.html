로컬 LLM 개발을 시작할 때 알아야 할 핵심 지식

로컬 환경에서 대규모 언어 모델을 구동하고 개발하기 위해 필요한 VRAM 계산법, 양자화 포맷, 추론 엔진 선택 기준을 정리했습니다.

클라우드 인공지능 API는 인프라 구축 없이 언어 모델 기능을 쓸 수 있지만, 사내 기밀이나 개인정보를 외부로 전송하기 어려운 한계가 있습니다. 호출 횟수에 비례해 늘어나는 토큰 비용과 네트워크 지연도 지속적인 서비스 개발에 부담이 됩니다.

자체 하드웨어에서 모델을 실행하는 LLM(Large Language Model: 대규모 언어 모델) 개발 환경은 네트워크 연결 없이도 데이터를 안전하게 처리합니다. 개발 과정에서 수만 번의 프롬프트 호출을 비용 없이 실험할 수 있는 점도 이점입니다. 다만 로컬 환경에서는 물리적 하드웨어 자원이 제한되므로, 파라미터 크기에 따른 메모리 사용량과 양자화 포맷의 특성을 파악해야 안정적인 개발 환경을 구성할 수 있습니다.

메모리와 하드웨어 요구사항 계산#

LLM 추론(Inference) 단계에서는 GPU(Graphics Processing Unit: 그래픽 처리 장치)의 연산 속도(FLOPS)보다 VRAM(Video Random Access Memory: 비디오 램)의 용량과 메모리 대역폭이 토큰 생성 속도를 결정합니다. 단어를 하나 생성할 때마다 모델의 모든 가중치를 메모리에서 읽어와야 하기 때문입니다.

구동에 필요한 최소 메모리는 모델의 파라미터 수와 가중치 데이터 정밀도로 계산합니다. FP16(16-bit Floating Point: 16비트 반정밀도 부동소수점) 형식의 원본 가중치는 파라미터 1개당 2바이트를 차지합니다.

필요 메모리 = 파라미터 수 × 가중치 바이트 수 + KV 캐시 및 런타임 여유분(약 20%)

8B(80억 개) 파라미터 모델을 FP16 정밀도로 올리면 순수 가중치만 16GB를 차지합니다. 대화 문맥을 유지하기 위한 KV 캐시(Key-Value Cache: 키-값 캐시)와 실행 버퍼를 더하면 최소 20GB 이상의 메모리가 필요합니다. 70B 모델은 FP16 기준으로 140GB 이상의 VRAM이 필요해 일반 개인용 그래픽 카드로는 구동할 수 없습니다.

하드웨어 환경에 따라 선택지가 나뉩니다.

  • NVIDIA GPU: CUDA(Compute Unified Device Architecture: 쿠다) 생태계의 지원으로 연산 속도가 빠르고 다양한 서빙 프레임워크를 그대로 씁니다. 다만 소비자용 제품군인 GeForce RTX 4080(16GB), RTX 4090(24GB) 등은 VRAM 한계가 있어 단일 카드로 70B급 모델을 올리기 어렵습니다.
  • Apple Silicon(M 시리즈): CPU와 GPU가 물리 메모리를 함께 쓰는 통합 메모리(Unified Memory Architecture: 통합 메모리 아키텍처) 구조입니다. 64GB나 128GB 메모리를 장착한 Mac에서는 별도의 고가 기업용 GPU 없이 70B 모델을 통째로 올려 구동할 수 있습니다. 초당 800GB 수준의 메모리 대역폭(M2 Ultra 기준)을 제공해 추론 속도도 안정적입니다.

양자화와 모델 파일 포맷#

제한된 메모리에서 대형 모델을 실행하려면 양자화(Quantization: 모델 가중치 정밀도 축소) 기술이 필요합니다.

양자화는 16비트 부동소수점 가중치를 8비트나 4비트 정수(INT8, INT4) 형태로 압축하는 기법입니다. 정밀도를 낮추면 모델의 언어 표현력이 미세하게 떨어지지만, 메모리 사용량을 4분의 1 수준으로 줄여 토큰 생성 속도를 높입니다. 8B 모델을 4비트로 양자화하면 가중치 용량이 약 5GB 안팎으로 줄어들어 일반 노트북에서도 충분히 구동할 수 있습니다.

주로 쓰이는 모델 파일 포맷은 다음과 같습니다.

  • GGUF(GPT-Generated Unified Format: 양자화 모델 저장 포맷): llama.cpp 프로젝트의 표준 바이너리 형식입니다. 모델 아키텍처 정보, 토크나이저 설정, 양자화 가중치를 단일 파일로 묶습니다. GPU VRAM이 부족할 때 일부 레이어만 시스템 RAM에 올리는 분할 적재(Offloading)를 지원해 일반 PC와 Mac 환경에서 널리 쓰입니다.
  • AWQ(Activation-aware Weight Quantization: 활성화 인식 가중치 양자화): 추론 과정에서 중요한 역할을 하는 핵심 가중치를 보호하며 4비트로 압축하는 기법입니다. 추론 정확도 손실이 적고 NVIDIA GPU의 텐서 코어에 최적화되어 서버 환경 서빙에 주로 쓰입니다.
  • EXL2(ExLlamaV2 format: ExLlamaV2 전용 가중치 포맷): 소수점 단위의 가변 비트레이트 양자화를 지원합니다. NVIDIA GPU 환경에 최적화되어 단일 그래픽 카드에서 빠른 토큰 생성 속도를 냅니다.

로컬 추론 엔진과 서빙 런타임#

모델 파일을 내려받은 뒤에는 가중치를 메모리에 올리고 연산을 스케줄링하며 외부 요청을 받아 응답을 넘겨주는 추론 엔진이 필요합니다.

사용자 코드 (Python / LangChain)
  → HTTP POST /v1/chat/completions
  → 추론 엔진 (Ollama / vLLM / llama.cpp)
  → 하드웨어 가속기 (CUDA / Metal / CPU)

프로젝트 규모와 배포 환경에 따라 도구를 선택합니다.

  • Ollama: 개인 개발 환경 구축에 가장 적합한 도구입니다. 단일 바이너리로 설치되며 모델 다운로드와 실행을 명령어 한 줄로 처리합니다. 백그라운드 서비스로 상주하며 OpenAI 호환 API를 기본 포트(11434)로 제공합니다.
  • llama.cpp: 순수 C/C++로 구현된 고성능 추론 엔진입니다. 외부 런타임 의존성이 없으며 Apple Metal, NVIDIA CUDA, CPU 등 대부분의 하드웨어를 지원합니다. 정밀한 메모리 제어와 커스텀 빌드가 필요할 때 씁니다.
  • vLLM(vLLM: 고성능 분산 LLM 서빙 프레임워크): 대규모 동시 요청 처리에 특화된 서빙 프레임워크입니다. PagedAttention 기술을 적용해 여러 사용자가 동시에 요청할 때 생기는 KV 캐시 메모리 낭비를 줄이고 GPU 처리량을 극대화합니다. 팀 단위 개발 서버나 사내 API 서빙에 알맞습니다.

로컬 LLM과 애플리케이션 연동 개발#

로컬 엔진은 공통적으로 REST API(Representational State Transfer API: 웹 표준 인터페이스) 엔드포인트를 제공합니다. 특히 OpenAI의 표준 엔드포인트 규격(/v1/chat/completions)을 지원하므로, 기존 SDK 코드의 접속 주소(base_url)만 바꾸면 로컬 모델로 전환할 수 있습니다.

Ollama를 이용한 로컬 서버 실행#

터미널에서 모델을 내려받고 실행합니다.

# Llama 3.1 8B 양자화 모델 다운로드 및 실행
ollama run llama3.1:8b

실행과 동시에 11434 포트로 HTTP 서버가 열립니다. curl 명령으로 동작을 확인합니다.

curl http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "llama3.1:8b",
    "messages": [
      {"role": "user", "content": "로컬 LLM 구동 시 VRAM이 중요한 이유를 1문장으로 요약해줘."}
    ],
    "temperature": 0.2
  }'

Python 코드 연동#

Python 애플리케이션에서는 공식 openai 라이브러리를 사용하되 base_url을 로컬 서버로 지정합니다. 로컬 환경은 API 키 검증을 하지 않으므로 임의의 문자열을 넣습니다.

from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama",
)

response = client.chat.completions.create(
    model="llama3.1:8b",
    messages=[
        {"role": "system", "content": "간결하고 정확하게 답변하세요."},
        {"role": "user", "content": "GGUF 포맷의 장점이 무엇인가요?"},
    ],
    temperature=0.3,
)

print(response.choices[0].message.content)

이 연동 구조를 쓰면 로컬 환경에서 프로토타입을 테스트하고 로직을 검증한 뒤, 고성능 모델이 필요할 때만 접속 주소를 클라우드 API로 바꿀 수 있습니다.

사내 문서를 기반으로 답변하는 RAG(Retrieval-Augmented Generation: 검색 증강 생성) 시스템을 개발할 때도 로컬 LLM과 임베딩 모델(예: BAAI의 bge-m3)을 벡터 데이터베이스와 결합하면, 데이터가 외부로 유출되지 않는 완전한 폐쇄망 질의응답 시스템을 구축할 수 있습니다.

용어 설명#

LLM#

Large Language Model(대규모 언어 모델). 수십억 개 이상의 매개변수를 방대한 텍스트 데이터로 학습시켜 인간의 언어를 이해하고 생성하는 인공신경망 모델입니다. (Meta Llama)

GPU#

Graphics Processing Unit(그래픽 처리 장치). 수천 개의 연산 코어를 이용해 대규모 행렬 연산을 병렬로 처리하는 하드웨어 가속기입니다. (NVIDIA Developer)

VRAM#

Video Random Access Memory(비디오 램). 그래픽 카드에 장착되어 GPU 코어가 초고속으로 접근할 수 있는 전용 고대역폭 메모리입니다.

FP16#

16-bit Floating Point(16비트 반정밀도 부동소수점). 1개의 부동소수점 숫자를 16비트(2바이트)로 표현하는 데이터 형식입니다.

KV 캐시#

Key-Value Cache(키-값 캐시). 트랜스포머 모델이 이전 토큰들을 매번 재연산하지 않도록 중간 어텐션 연산 결과(Key, Value)를 메모리에 저장해 두는 버퍼입니다.

CUDA#

Compute Unified Device Architecture(쿠다). NVIDIA가 개발한 GPU 범용 병렬 컴퓨팅 플랫폼 및 프로그래밍 모델입니다. (NVIDIA CUDA)

통합 메모리#

Unified Memory Architecture(통합 메모리 아키텍처). CPU와 GPU가 데이터를 복사하지 않고 단일 고대역폭 메모리 주소 공간을 함께 사용하는 구조입니다. (Apple Developer)

양자화#

Quantization(모델 가중치 정밀도 축소). 모델의 매개변수를 16비트 부동소수점에서 8비트나 4비트 정수로 변환하여 메모리 사용량을 줄이고 추론 속도를 높이는 기법입니다.

GGUF#

GPT-Generated Unified Format(양자화 모델 저장 포맷). llama.cpp 생태계에서 모델 아키텍처 정보와 가중치를 단일 바이너리 파일로 관리하기 위해 고안한 표준 포맷입니다. (GGUF Document)

AWQ#

Activation-aware Weight Quantization(활성화 인식 가중치 양자화). 추론 시 활성화 값의 크기를 바탕으로 핵심 가중치를 보호하며 4비트로 압축하는 양자화 기술입니다. (AWQ GitHub)

EXL2#

ExLlamaV2 format(ExLlamaV2 전용 가중치 포맷). NVIDIA GPU 환경에서 극도로 빠른 추론 속도를 내도록 설계된 가변 비트레이트 양자화 포맷입니다. (ExLlamaV2)

vLLM#

Virtual Large Language Model 서빙 프레임워크. PagedAttention 알고리즘을 사용해 KV 캐시 메모리 낭비를 줄이고 동시 요청 처리량을 극대화한 오픈소스 분산 서빙 엔진입니다. (vLLM Documentation)

REST API#

Representational State Transfer API(웹 표준 인터페이스). HTTP 프로토콜을 사용해 자원을 주고받는 웹 애플리케이션 아키텍처 스타일입니다.

RAG#

Retrieval-Augmented Generation(검색 증강 생성). 질문과 관련된 외부 문서 데이터를 검색해 프롬프트 문맥에 주입한 뒤 언어 모델이 답변하도록 만드는 기술입니다.
