Prisma는 Node.js와 TypeScript에서 쓰는 오픈소스 ORM(Object-Relational Mapping: 객체 관계 매핑)입니다. 이 글은 Prisma 7 문서를 기준으로 정리했고, 확인한 2026-11-01에는 npm에 8.0.0-rc 버전도 올라와 있었습니다. 8 문서에는 $transaction에 쿼리 배열을 넘기던 형태가 없어졌다고 적혀 있어서, 버전을 올릴 때는 문서를 다시 봐야 합니다. 이 글의 코드는 공식 퀵스타트를 따라 정리한 것이고 직접 실행해서 확인한 것은 아닙니다.

Prisma는 무엇으로 이루어져 있나#

Prisma ORM은 세 부분으로 나뉩니다. Prisma Client는 스키마에서 자동으로 만들어지는 타입 안전 쿼리 도구이고, 결과는 평범한 JavaScript 객체로 돌아옵니다. Prisma Migrate는 마이그레이션을 관리하고, Prisma Studio는 데이터를 눈으로 보고 고치는 화면입니다. 이 중 Studio만 오픈소스가 아니고 로컬에서만 실행됩니다. (What is Prisma ORM?)

시작점은 schema.prisma 파일입니다. 데이터베이스 종류를 적는 datasource, 클라이언트를 어디에 만들지 정하는 generator, 테이블에 대응하는 model을 한 파일에 적습니다. Prisma 7부터 접속 주소는 스키마가 아니라 prisma.config.ts에 둡니다.

generator client {
  provider = "prisma-client"
  output   = "../generated/prisma"
}

datasource db {
  provider = "sqlite"
}

model User {
  id    Int     @id @default(autoincrement())
  email String  @unique
  name  String?
  posts Post[]
}

model Post {
  id       Int    @id @default(autoincrement())
  title    String
  author   User   @relation(fields: [authorId], references: [id])
  authorId Int
}

모델을 고친 뒤에는 두 가지 일을 해야 합니다. prisma migrate dev는 바뀐 부분을 SQL(Structured Query Language: 구조화 질의 언어) 마이그레이션 파일로 만들어 데이터베이스에 적용하고, prisma generate는 코드에서 쓰는 클라이언트와 타입을 다시 만듭니다. 한 파일이 데이터베이스 쪽과 코드 쪽을 함께 이끄는 구조입니다.

생성된 클라이언트로 쓰는 쿼리는 이렇게 생겼습니다. Prisma 7은 데이터베이스 드라이버를 어댑터로 따로 넘기는 방식이라, SQLite라면 @prisma/adapter-better-sqlite3를 설치해 PrismaClient에 넣어야 합니다.

const user = await prisma.user.create({
  data: {
    email: 'alice@example.com',
    name: 'Alice',
    posts: { create: { title: 'Hello World' } },
  },
  include: { posts: true },
})

사용자와 글을 한 번에 만들고, include로 관계까지 같이 가져옵니다. 여러 테이블을 묶는 쿼리를 직접 쓰지 않아도 되고, 결과의 타입도 스키마에서 정해집니다.

다른 ORM과 비교#

Prisma 문서는 전통적인 ORM을 Active Record와 Data Mapper로 나누고, Prisma를 Data Mapper의 한 변형으로 봅니다. 스키마 하나가 타입, 마이그레이션, 매핑을 모두 정하기 때문에 코드의 클래스와 데이터베이스 스키마를 따로 맞춰 줄 필요가 줄어든다는 설명입니다. (Is Prisma an ORM?)

같은 TypeScript 진영의 TypeORM과 Drizzle은 출발점이 다릅니다. TypeORM은 클래스에 @Entity, @Column 같은 데코레이터를 붙여 엔티티를 만들고, Data Mapper와 Active Record를 둘 다 지원합니다. (TypeORM) Drizzle은 “SQL을 알면 Drizzle도 안다"는 방향이라, 테이블을 TypeScript 코드로 선언하고 SQL과 닮은 API로 쿼리를 씁니다. 관계 데이터를 한 번에 가져오는 별도 API도 있습니다. (Drizzle ORM)

Prisma만의 특징은 스키마가 TypeScript가 아닌 별도 언어라는 점입니다. 덕분에 한 파일만 보면 데이터 모델 전체가 보이고 클라이언트와 마이그레이션이 거기서 나오지만, 스키마를 고칠 때마다 generate를 다시 돌려야 한다는 번거로움도 같이 옵니다. 반대로 Drizzle이나 TypeORM은 스키마가 곧 TypeScript 코드라서 별도 생성 단계가 필요 없습니다. 어느 쪽이 낫다기보다, 스키마를 코드 옆에 두고 싶은지 독립된 문서로 두고 싶은지의 차이에 가깝습니다.

복잡한 쿼리는 ORM 전반의 약점입니다. Prisma 문서도 ORM의 단점으로 일부 복잡한 쿼리를 표현하기 어렵다는 점을 들고, 그럴 때는 SQL을 직접 쓰면 된다고 안내합니다. Prisma에는 .sql 파일에 쓴 쿼리에서 타입을 만들어 주는 TypedSQL이 있는데, 확인한 문서에서는 typedSql 미리보기 기능을 켜야 쓸 수 있었습니다. (TypedSQL)

다음 글에서는 ORM을 쓰지 않고 SQL을 직접 쓰는 경우와 비교하고, AI 도구로 개발할 때 ORM이 어떤 영향을 주는지 정리합니다. 2. ORM과 SQL 직접 작성, AI 도구와의 궁합

용어 설명#

ORM#

Object-Relational Mapping(객체 관계 매핑). 코드의 객체와 관계형 데이터베이스의 테이블을 이어 주어, SQL을 직접 쓰지 않고도 데이터를 읽고 쓰게 하는 도구입니다. (Prisma 문서)

SQL#

Structured Query Language(구조화 질의 언어). 관계형 데이터베이스에 데이터를 묻고 바꾸는 표준 언어입니다. (TypedSQL)

마이그레이션#

Migration. 데이터베이스 구조(테이블, 컬럼)가 바뀐 내용을 파일로 기록하고 순서대로 적용하는 방식입니다. (Prisma Migrate)

Active Record#

모델 클래스가 테이블과 거의 일대일로 대응하고, 객체 하나가 행 하나를 감싸 저장까지 맡는 방식입니다. (Is Prisma an ORM?)

Data Mapper#

엔티티 클래스는 데이터베이스를 모르고, 별도의 매퍼가 데이터 이동과 SQL 생성을 맡는 방식입니다. (Is Prisma an ORM?)
